# oasis

An OpenSubsonic music server that merges your local library with streaming services into one library. Clients see ordinary tracks and never learn where a track comes from.

It pairs with **mirage**, a fooyin fork that shows the server's library as if it were on your machine, and **caravan** (com.zakius.caravan), an Android Subsonic client romanized by roma. Both caravan and **dragoman** (com.zakius.dragoman), the YouTube Music app that was roma ytm until 2026-11-09, are built in [caravanserai](https://github.com/zakius/caravanserai).

## Status

Early. oasis serves a local music library over the Subsonic API, so any Subsonic client works: Feishin, Symfonium, DSub, Supersonic, and others.

With YouTube Music on (Services, below), searches also return YouTube Music songs after the local matches. A YouTube Music result that matches a local track (same artist and title, length within 5 seconds) shows up as the local track. YouTube Music tracks join the library while they are starred or in a playlist, and download into the cache when they join. Other tracks download when first played. Uncached tracks start in about 0.2 seconds: oasis gets the audio URL with one visionOS player request, plays straight from YouTube, and fills the cache in the background. If that client stops working, oasis falls back to yt-dlp, whose URLs only work after about 5 seconds. No account is needed yet. Running from source needs `node` or `bun` on `PATH`; the container image includes node.

## Accounts

Open `http://<host>:4533/` and sign in with your user and password. Each user turns on their own services on the Services page (`/services`), and links their own accounts there. A service switched on unfolds its sign-in and settings; one that needs an account (Qobuz, Tidal, ListenBrainz) is used only once it is linked, SoundCloud and Bandcamp work without one and do more with one, and switching a service off forgets its sign-in. The page groups them as streaming (YouTube Music, Qobuz, Tidal, Bandcamp, SoundCloud), plays and recommendations (Last.fm, ListenBrainz, and the user's lists of other servers that take plays) and previews (Deezer, Apple Music).

Admins choose on the same page what the server offers: each service, and under it each of its capabilities: full songs; signed-in songs (SoundCloud's Go+ songs, with the user's sign-in); previews; radios (Deezer, Tidal and SoundCloud as radio sources, and Deezer's related artists); account features (a YouTube Music account's mixes and history, a SoundCloud account's likes and playlists, a Bandcamp account's purchases and wishlist, the playlists ListenBrainz makes for the user, a Tidal account's mixes). Each list of other servers that take plays has one switch. Users only see and use what is offered; a sign-in stays while its capability isn't. Every service starts offered, YouTube Music as `[ytmusic] enabled` in `oasis.toml` says; the page's switches then decide while oasis runs. YouTube Music's lyrics and share links follow only its main switch. A song from a service the user hasn't turned on plays once its audio is kept here (someone with the service played it); before that, `stream` fails with a message, and apps that take unavailable songs get it with `playable: false`.

- **YouTube Music**: searching and streaming need no account. For mixes, library playlists and play history, paste the "Copy as cURL" of a `browse` request (or its request headers, or the `Cookie` value) from a signed-in music.youtube.com tab, as the page explains step by step. oasis checks the sign-in and shows the account name. Clients can also link it themselves: `oasisLinkYouTubeMusic` takes `cookie` (the Cookie header) and optional `authUser`, which roma used to hand over its own Google sign-in until 2026-11-01; caravan has no YouTube code, so accounts are linked on the Services page. `oasisUnlinkYouTubeMusic` removes it.
- **Last.fm**: similar songs and radios need no account. "Sign in with Last.fm" goes through Last.fm's own page, for scrobbling and stations. The server needs `[lastfm] api_key` and `secret`.
- **ListenBrainz**: paste the user token. oasis checks it. The playlists ListenBrainz makes for the user (Weekly Jams, Weekly Exploration, Daily Jams, the yearly ones) show up as read-only playlists owned by "ListenBrainz", read again every 6 hours with ListenBrainz's "created for" playlists API: the newest of each kind that hasn't expired. Their songs are found as radios find theirs (below), and a song nothing plays comes only to apps that take those, for users who see them. They don't join the library.
- **Other Last.fm-compatible servers**: each user keeps a list of servers that speak Last.fm's API, and plays are scrobbled to each one switched on too. "Sign in with Libre.fm" adds Libre.fm; any other server (GNU FM's, for example) is added by its API address, with its sign-in page if that isn't the API address's `../api/auth/`. oasis signs in through the server's own page, as with Last.fm, with its own API key: Libre.fm takes any key and secret. Each entry has a name (its host unless the user gives one), a switch and Remove.
- **Other ListenBrainz-compatible servers**: a list the same way, of servers that take ListenBrainz's submissions, such as Maloja and Koito (their API is at `/apis/listenbrainz/1/`). The user gives the API address and their token there; oasis checks the token with `validate-token`, or, on a server without it, by sending a song playing now, and says when the server refuses it. oasis calls these servers from its own host, so their addresses must be ones that host reaches. Addresses must be http or https.
- **SoundCloud**: paste the value of the `oauth_token` cookie of a signed-in soundcloud.com tab; oasis checks it with SoundCloud and shows the account name. With a Go+ subscription, songs only Go+ plays in full play in full (signed-in songs), as Go+'s 256 kbit/s AAC. The user's likes, own playlists and liked playlists show up as read-only playlists owned by "SoundCloud", read again every 6 hours, with the songs SoundCloud plays the user in full.
- **Bandcamp**: paste the value of the `identity` cookie of a signed-in bandcamp.com tab; oasis checks it with Bandcamp and shows the fan name. See "Getting music" for what it does.

Users in `oasis.toml` are admins, and their passwords are set there. Admins add and remove other users on `/admin`; anyone changes their own password on the account page. A user's password signs in to the dashboard only, and is stored hashed (scrypt).

Subsonic apps sign in with app passwords instead: each user makes one per app on `/account/apps`, names it, and revokes it there. oasis makes them random, so one that leaks was never used anywhere else and opens only the API; Subsonic's token login needs the secret itself, so app passwords are stored as given. An app password is also an API key (OpenSubsonic's `apiKeyAuthentication`), sent as `apiKey` without `u`. Apps can't change users or passwords: `createUser`, `updateUser`, `deleteUser` and `changePassword` are refused, and `getUser` and `getUsers` still answer. A password stored as given by an older oasis becomes an app password named "Apps signed in before app passwords", so apps keep working, and the same password, hashed, signs in to the dashboard; revoke it once the apps have their own.

Each play a client reports (`scrobble`) goes to the services its user linked and has on, and to each of the user's other servers switched on. oasis keeps each play until each service takes it, retrying each on its own, so plays made offline or during an outage arrive later and one server down holds up no other. Plays of local tracks reach YouTube Music history too: oasis finds the same song there (same title, length within 5 seconds) and remembers the match. Clients should not scrobble to Last.fm themselves, or plays count twice.

Recommendations mix several methods, taking turns so library songs come throughout: YouTube Music's radio for the song, Last.fm's similar tracks and the library songs of Last.fm's similar artists (with `[lastfm] api_key`), ListenBrainz's LB Radio, Deezer's radio of the artist (its public API, no account), Tidal's radios of the song and of its artist (with the user's Tidal account), SoundCloud's related tracks of the song (with or without the user's sign-in), the artist's other library songs, songs played within an hour of it, and library songs of the same genre, closest in year first. Each service counts for a user who has it on, Deezer, Tidal and SoundCloud while their radio capability is offered; each is also a radio source of its own (Radio, on the dashboard). Songs that aren't on YouTube Music still get a full list from the library. Local copies stand in for streaming tracks everywhere, other uploads of a song already known fold into it, and a stream that gains a local copy is moved onto it (stars, plays and playlist entries) at the next scan.

A song Last.fm, ListenBrainz, Deezer, Tidal or SoundCloud suggests plays from the library, else from the best answer of the streaming services the user has on (Services): YouTube Music and these, all asked at once.

- **Qobuz** and **Tidal**: FLAC at CD quality, with the user's own account that streams. The user links Qobuz with its email and password (oasis keeps the sign-in Qobuz returns, not the password) and Tidal with a code entered on Tidal's site. oasis reads the Qobuz web player's app id and secrets from the player's own script when the account is linked. A linked Tidal account's mixes (My Mix, My Daily Discovery, My New Arrivals) show up as read-only playlists owned by "Tidal", read again every 6 hours, their songs found as radios find theirs; they don't join the library.
- **Bandcamp**: the full-length 128 kbit/s MP3 that most Bandcamp tracks stream, from the artist's own page, through yt-dlp. No account. Bandcamp answers scripts with a bot check, so yt-dlp copies Firefox's connection (browser impersonation, with the `curl_cffi` package oasis installs).
- **SoundCloud**: full-length AAC from the artist's own account, through SoundCloud's web player API. Tracks that only SoundCloud Go+ plays in full give 30 s previews and are left out, unless the user signed in with Go+. No account otherwise.

A song counts as found when its artist and title match and it is longer than a 31 s preview. The answers rank as a full lossless song, then a full lossy song by bitrate (YouTube Music wins a tie), then a preview. A full lossless song ends the wait at once; otherwise, after the best answer so far came at t seconds, oasis waits min(0.3·t, 3 s) for a better one, counted again from each better answer, and never past the request's own deadline. Each service's answer, a miss too, is kept for an hour with the time it took, and counts as coming at that time; the log has each service's time for each song.

Its audio is downloaded into `streams` beside the database when first played, with the account of the user playing it, and played from there for everyone; once a day oasis deletes the audio no song plays any more, such as a stream that a local copy replaced. Qobuz's FLAC, Bandcamp's MP3, Tidal's file (or its DASH segments, one after another) and SoundCloud's single-file encodings play through oasis at once while the download runs, as YouTube Music's do, seeking included; SoundCloud's HLS-only songs are downloaded first. These services are used through their apps' own interfaces, not public ones: they may stop working, and they may close an account that streams this way. Full Deezer streams aren't supported: they are encrypted, and the key isn't something to publish here.

A song that no source has is a song nothing can play. Apps that ask for those (the OpenSubsonic extension `unavailableSongs`, [docs/unavailable-songs-extension.md](docs/unavailable-songs-extension.md)) get them in similar songs, radios and albums only MusicBrainz has, with `playable: false`, their MusicBrainz album and their artist. Other apps never get them, and each user can turn them off on the dashboard. Starring one wants its album (earliest official studio album, else an EP or single), and unstarring it lets the album go unless you starred the album yourself; once the album is here, or a service has the song, its stars and playlist entries move to the song that plays. The dashboard's song page shows them too, and lists similar songs on request with a star button for each song nothing plays. Radios count only playable songs toward the 30 they keep queued.

Such a song can still play a 30-second preview, for users who turn previews on: Deezer's public API and Apple's iTunes Search API (Services, Previews; both are off at first), SoundCloud's public clips of Go+ songs, Qobuz's samples, and Tidal's previews. Deezer, Apple and SoundCloud need no account. Qobuz answers nothing without a signed-in account: any Qobuz account gets samples of what it can't stream, so one without a subscription can be linked for samples alone while previews are offered. Tidal's need the user's Tidal account. Only apps that take songs nothing can play get previews (the song has `preview: 30` and `stream` plays the clip), so plain Subsonic apps never play a clip as if it were the song. The dashboard plays them on the song page and in similar songs. Clips are kept in `streams` too.

`getArtistInfo` and `getArtistInfo2` with Subsonic's `includeNotPresent=true` also list the similar artists the library lacks, when Last.fm knows their MusicBrainz id, as artists only MusicBrainz has (`ar-mb-…`): any client can open and follow them.

- Clients' "instant mix" or "similar songs" (`getSimilarSongs2`) returns YouTube Music's radio for the song, album or artist.
- `getArtist` lists the library's albums by the artist, then the rest of their YouTube Music discography (albums, singles and EPs, newest first, with `releaseTypes`); opening one fetches its tracks. The artist's YouTube Music page is fetched on first open and kept for a day. These albums don't join the library lists.
- `getTopSongs` lists an artist's most played library tracks, then their YouTube Music top songs.
- `getArtistInfo2` adds YouTube Music's description and photo, with Last.fm's biography taking over when there is one.
- `getArtistInfo2` returns the Last.fm biography and the similar artists that are in the library, with the library's artists among Deezer's related ones for a user who has Deezer's radios.
- Opening an album known only from streaming search or radio fetches the whole album.
- Radio playlists grow while you listen and keep 30 unplayed tracks queued. Each user gets a "Radio" playlist that follows everything they play, mixing YouTube Music radio and Last.fm picks for the last few songs. Any playlist whose name starts with "Radio" grows the same way from the songs played in it, so a playlist named "Radio" with one song is a station for that song. Radio tracks don't join the library.
- Ready-made playlists, owned by "oasis", reach every app: "Your top tracks", the user's 50 most played songs of the last three months, and "Forgotten favourites", up to 50 songs they played at least 5 times but not in the last three months, both made again daily from their plays here with only the songs that play for them, and absent while empty. With Last.fm linked, the "Last.fm top tracks" (last three months) and "Last.fm loved tracks" stations come too, so apps that can't start a station still get them; they grow as stations do. Each user ticks the ones shown under Ready-made playlists on the dashboard; unticking one removes it from their apps. Their songs don't join the library.
- The standard album lists "frequent" and "recent" (`getAlbumList2`) go by each user's own plays.

With YouTube Music linked, each user's personal mixes (My Supermix, the themed My Mixes, Discover Mix, Replay Mix, Archive Mix and others) and library playlists (Liked Music and the playlists they made or saved) appear as read-only playlists with owner `YouTube Music` and their cover art. For clients using the OpenSubsonic extension `oasis` ([docs/oasis-extension.md](docs/oasis-extension.md), `oasis=1` on each request), mixes also carry `oasisMix: true`, and every mirrored playlist carries its YouTube playlist id as `youtubeId`. `getPlaylists` lists the mixes first in YouTube Music's order (My Supermix, My Mix 1–7, Discover, New Release, Replay, then others by title), then Liked Music, then the rest by name. oasis refreshes them every 6 hours. Their tracks, albums and artists are in the library lists while the mix holds them, but they only download when played, starred or added to your own playlist.

Lyrics (`getLyricsBySongId`, OpenSubsonic `songLyrics`, and `getLyrics`) come from a `.lrc` file next to the track or lyrics tags in the file. Otherwise oasis asks the sources roma uses at once: YouTube Music, LRCLIB, NetEase, KuGou and LyricsPlus. It picks by roma's rules, with YouTube Music's text as the reference: word-timed lyrics that match it, then YouTube Music's line-timed lyrics, then other synced lyrics that match, then YouTube Music's plain text. Credit lines are dropped. Results are cached, and a miss is retried after a day. NetEase and KuGou are unofficial APIs and may change.

Names and lyrics in other scripts come romanized for clients that ask, through the OpenSubsonic extension `romanization` ([docs/romanization-extension.md](docs/romanization-extension.md)): Japanese in Hepburn, Chinese in pinyin, Korean, Cyrillic and Greek in their usual Latin forms, as roma romanizes them. Search finds songs, albums and artists by their romanized names whatever the client asks.

Desktop clients (mirage) send ripped CDs and albums through the OpenSubsonic extension `upload` ([docs/upload-extension.md](docs/upload-extension.md)): oasis tags them from MusicBrainz or the client's tags, checks and files them as it does downloads, and scans them in. Admins only.

`stream` transcodes when a client asks for `format=opus` (in WebM), `mp3` or `aac`, or for a `maxBitRate` below the file's bitrate; `timeOffset` starts partway in. Transcoding needs `ffmpeg` on `PATH`, which the container includes. Without it, oasis sends the original file.

## Getting music

With `[torbox]` (with `downloads`) and `[prowlarr]`, starring an album or artist (`star` with `albumId` or `artistId`, as clients do for "add to library") makes oasis get it: a starred album is downloaded, a starred artist followed, its missing albums and new releases downloaded. `unstar` lets it go; files stay. Clients need nothing beyond standard Subsonic. oasis searches Prowlarr's indexers itself, downloads through TorBox, and places the files in the library itself; nothing on the host seeds or uploads.

```toml
[torbox]
rdt_db = "/rdt/rdtclient.db"   # rdtclient's database, read from a copy for the TorBox key and its torrents
downloads = "/downloads/oasis" # oasis's staging folder
# max_active = 8               # TorBox torrents active at which no download starts: Pro has 10, two stay free for anime
# stall_hours = 1              # no progress this long: the torrent is dead
# dry_run = true               # the doctor logs what it would do and changes nothing

[prowlarr]
url = "http://prowlarr:9696"
api_key = "…"                  # Prowlarr's config.xml
# tag = 2                      # the music indexers' tag

[acquire]
secondary_types = ["Soundtrack"] # besides albums with none
# bundles = false                # no bundle searches
```

oasis keeps the catalogue from MusicBrainz (see `oasis/acquire.py`), and a worker reconciles it with the stars after every star or unstar and every minute. A starred album resolves to its release group: from the library's tags, else by an exact title match among the artist's release groups (the artist from tags, else by name or alias; collaboration credits are tried artist by artist). A followed artist's albums, EPs and singles are read once a day, with no secondary type or one of `secondary_types`, and only those with an official release. Left out are repackages (best-ofs, deluxe and anniversary editions, re-recordings, albums 60 % of whose songs are on earlier ones) and singles whose songs are all on the artist's albums and EPs; starred albums, albums with files and the albums and EPs Lidarr was looking for when oasis took over from it never are. An album is here once the library holds as many of its tracks as its smallest edition has (video discs aside). One missing album is searched a minute, while TorBox has a slot: starred ones first, then albums and EPs, then singles, those never searched first, newest first. One that finds nothing is searched again after 6 hours, then twice as long each time up to a week; singles after a week, then up to four. An album here only lossy gets a lossless search weekly. Unstarring or unfollowing drops the albums from the catalogue; files stay. Names with no MusicBrainz match are looked up again after 30 minutes, errors and timeouts after 5. The Status panel counts the albums still to find.

With `oasis=1` (the `oasis` extension), albums and artists carry `oasisWanted`: `wanted`, `downloading` or `failed`, with the reason in `oasisWantedError` (for example "searched, no release found yet"), and nothing once an album is here, an artist is followed, or nobody wants it.

The search (see `oasis/releases.py`) asks Prowlarr's music indexers for "artist album", then the album alone when the title is distinctive, then the album with the artist's names in other scripts (MusicBrainz aliases), with brackets and quotes dropped, and stops at the first query that finds a usable release. A name must hold the artist (under any of their names) and the album title as whole words, case, accents, punctuation and full-width forms aside; kana, kanji and Hangul count character by character, so `[2022.09.07] Creepy Nuts 3rdアルバム「アンサンブル・プレイ」[FLAC]` matches. Names with variant words the title lacks (live, instrumentals, acapellas, karaoke, remixes, deluxe, anniversary…), bundles (discographies, or the titles of two of the artist's albums), videos, disc images (`image+.cue`: the import takes a file per track), and sizes outside 20 MB–5 GB per disc are left out; a self-titled album or a title under 4 characters also needs the year, the title right after the artist, or the title in quotes. Lossless comes first, then what TorBox has cached (whatever its seeders), then MP3 320, V0, then seeders; a release TorBox hasn't cached needs a seeder. An album already here lossy only takes lossless.

An artist with two albums or EPs missing, or one a search found nothing for, also gets a bundle search weekly, in an album search's place: "Artist discography", "Artist" and the artist's names in other scripts. A release is a bundle when its name holds the artist and a bundle word (discography, complete, box set...) or two of the artist's album titles. Only bundles TorBox has cached count, read by their file lists: a folder whose name holds a wanted album's title (and its year, when the name has one), no variant word, and file names covering one of its editions is that album. The bundle with the most such albums goes to TorBox; only those albums' music and images are fetched, each is imported on its own, and the torrent is deleted from TorBox. A bundle none of whose albums imports is blocked. Disc images, partial albums and albums already here or downloading are left out.

The pick goes to TorBox with no seeding (see `oasis/download.py`); oasis fetches the music, cue sheets and cover art one file at a time (paced, two at once) into `downloads/<hash>/` at their paths inside the torrent, and imports them. It starts a download only while fewer than `max_active` torrents are active on the whole TorBox account, anime's included. A dead torrent, a TorBox error or a failed import blocks the release and searches the album again; a failed import's files stay 7 days.

The import (see `oasis/importer.py`) finds the MusicBrainz edition of the album the files are: every track of it must have a file with its title (or, failing that, its disc and track number) and a length within 5 s or 3 %; the edition with the most tracks wins, then the one with the closest lengths. It writes that edition's tags the way Picard names them, overwriting what the download had, and copies the files into the first library folder as `Artist/Year - Album/NN - Title.ext`: the MusicBrainz name of the release's first artist, the release group's first year, and the edition's titles. An album of several discs stays in one folder, its files named `1-01 - Title.ext`. It never overwrites a file: a track the library has already stays, unless the library's copy is lossy and the new one lossless; then the old file is deleted once the new one is in place. Before anything is placed, the download's FLACs are checked by their decoded audio (see `oasis/quality.py`): a FLAC made from an MP3 or AAC (a hard spectral cutoff below 19.6 kHz throughout) fails the import and blocks the release, so the next search picks another, even an MP3 one; a 24-bit file of 16-bit samples becomes 16-bit, sample for sample; one upsampled from 44.1 or 48 kHz is resampled back (to 16-bit for 44.1 kHz); any other file is recompressed with `flac -8` when that saves 3 %. Every rewrite keeps all metadata and is verified before it replaces the file. The album and song pages show what the checks found. Then oasis scans, and streams of the same songs move onto the files. All MusicBrainz requests of oasis, the credits' too, go one at a time, 1.1 s apart.

With `[torbox]`, a worker also keeps TorBox's active slots free every 5 minutes (see `oasis/doctor.py`), for oasis and for anime (Sonarr through rdtclient): it deletes the account's queued items (TorBox queues adds beyond the plan's slots, and rdtclient reports them failed), active torrents neither rdtclient nor oasis tracks, and torrents with no seeds and no progress for `stall_hours`, which rdtclient reports to Sonarr as failed. oasis's own downloads are left to it.

Any signed-in user can also find music on the dashboard: `/music` searches MusicBrainz for artists (by any name or alias, in any script: "Kenshi Yonezu" finds 米津玄師) or albums, and shows whether each is in the library, wanted or followed. An artist's page (`/music/artist/<MusicBrainz id>`) follows or unfollows it and lists its albums, EPs and singles, each with Want or Unwant. Wanting and following are starring: the dashboard stars the library's id, or `ar-mb-<id>` / `al-mb-<release group id>` for what only MusicBrainz has. `/music/wanted` lists every album oasis is looking for with its state (waiting for its search, not found yet, downloading with its progress, importing, failed and why), and can search one next, block the release downloading and try another, or give up on it (unwanted, and left out of its artist's catalogue; files stay). On an artist's page, an album oasis is searching for shows Unwant, also one wanted only because its artist is followed; one already in the library shows Unwant to the users who keep it there (by its star or a follow). A user who unwants an album in the library that nobody else wants asks the admins to remove it: the wanted page lists such requests, to remove or keep. Admins can remove any album in the library from its artist's page: its files are deleted, with its folder once no audio is left in it, everyone's stars of it are taken back, and a followed artist's catalogue leaves it out. In Subsonic clients that ask with `oasis=1` (the `oasis` extension), `search3` adds MusicBrainz artists and albums that neither the library nor YouTube Music has, for queries of 3 or more characters, after the other results; searches are kept a week. A search waits 3 seconds for MusicBrainz: when it is busy the answer goes out without them, and the next search for the same text has them. Such an artist lists its release groups, an album has no songs until it arrives, and starring them wants or follows them as for any other. Once one arrives, its stars and wants move to the library's id, and the old id keeps working.

A user signed in to Bandcamp (Services) has their purchases imported into the library as FLAC, and the albums on their wishlist wanted for them, while Bandcamp's account features are offered (see `oasis/bandcamp.py`). Both are read every 6 hours. Each purchase's release group is the one MusicBrainz links to its Bandcamp page, else the artist's of its title; the FLAC download is unpacked and imported like a torrent's, as an edition of that release group, unless the library has the album lossless already. A wished album is starred for the user once MusicBrainz knows it (a wished track, its album). An item MusicBrainz doesn't know, or whose import failed, is tried again a week later; `bandcamp_item` keeps what became of each. This needs no `[torbox]` or `[prowlarr]`.

Lidarr searched and imported before oasis did. Its tables `lidarr_rescue` and `catalogue_search` stay in the database. Usenet isn't supported.

## Run

```sh
python3 -m venv .venv
.venv/bin/pip install -e .
cp oasis.example.toml oasis.toml   # set library paths and a password
.venv/bin/oasis -c oasis.toml       # scans in the background, serves on port 4533
```

Or in a container. Put `oasis.toml` in `./config`, set its library path to `/music`, and run:

```sh
docker compose up -d --build
```

`compose.yaml` mounts `~/Music` read-only at `/music`. The container runs as UID 1000, so `./config` must be writable by that user; set `user:` in `compose.yaml` otherwise.

Point a Subsonic client at `http://<host>:4533`, with an app password. `oasis scan` runs a scan without serving. `oasis relocate` moves files placed under an older scheme (Lidarr's `Artist/Album (Year)`) to the import's names by their MusicBrainz tags; it only plans and checks the moves until given `--apply`, and should run while the server is stopped. Tracks keep their ids, so stars, plays and playlists stay, and the moves are written to `.oasis-renames-<date>.tsv` in the library. `oasis quality` runs the same checks over the library, beside the server and at the lowest CPU and I/O priority (`docker compose exec -d oasis sh -c 'oasis -c /config/oasis.toml quality >> /config/quality.log 2>&1'`); it resumes where it stopped and skips files dedupe shares. It lists lossy-sourced FLACs, and with `--delete-lossy` deletes them (their whole album when most of it is) and wants the album again; files without a MusicBrainz release group stay. The server rescans when a client calls `startScan`.

## Supported API

Browsing (`getArtists`, `getArtist`, `getAlbum`, `getSong`, `getIndexes`, `getMusicDirectory`), album lists, random songs, genres, `search2`/`search3` (an empty query lists everything, for clients that sync the whole library), stars, ratings, scrobbles, playlists, cover art (embedded or `cover`/`folder`/`front` images), and `stream`/`download` with HTTP range requests. Responses are XML or JSON (`f=json`), over GET or form POST.

With `oasis=1`, songs carry `youtubeId`, the YouTube video of the same song, when oasis knows it: always for YouTube Music tracks, and for local files once they're matched. `getSong` looks a local song up on YouTube Music the first time it's asked. Every client, with or without `oasis=1`, also gets the link to share as `shareUrl`, through the OpenSubsonic extension `shareUrl` ([docs/share-url-extension.md](docs/share-url-extension.md)).

Methods for podcasts, shares, bookmarks and internet radio return empty results.
